Inside the Transformer: How Attention Builds Context

Follow token rows through attention, a complete decoder block, and next-token selection; then recognize which architectural changes affect computation and memory.

Prerequisite: chapters 01-05, refreshed at point of use17 sectionsOriginal diagrams + reproducible tensor calculations

The engineering question

A request arrives as text. A response leaves as text. Between them, where does one token acquire information from another, and how do those contextual numbers become the next token? An architecture diagram should answer that question, not replace it with unexplained boxes.

We will calculate a tiny model, from input IDs to the next-token prediction. This makes the operations visible; it does not reveal a production model's thoughts. Read sections 1-11 in order. The early sections calculate individual parts, and section 11 joins them into one forward pass. Sections 12-15 explain training, memory and implementation choices. The Interview questions section has 20 prompts with explained answers.

Scope and assumptions

We choose the toy tokenization, coefficients, widths and probabilities to make the calculations easy to follow. They are not measured model outputs. Our main example is a decoder-only model with normalization before each branch; we also explain how the original encoder-decoder Transformer differs. Architectures vary. A weighted combination of numbers is not proof of factual accuracy or human-like understanding.

1. A sequence needs relationships, not just isolated features

A sequence is an ordered collection, such as token IDs. A hidden state is an intermediate numerical representation. In "The worker retried the job because it failed," context can help distinguish what "it" refers to. That sentence motivates exchanging information; it does not prove that a head reliably resolves pronouns.

A recurrent neural network, or RNN, carries a state from one position to the next. Recall chapter 5's toy rule: ht=xt+0.5ht−1h_t=x_t+0.5h_{t-1}ht​=xt​+0.5ht−1​. Here t is the position, x is its scalar input, and h0=0 is the starting state.

For inputs [2,0,1], first calculate h1=2+0=2. Use that result to calculate h2=0+0.5(2)=1. Then calculate h3=1+0.5(1)=1.5. The third step must wait for the second. The first input's contribution reaches h3 as 2(0.5)(0.5)=0.5, after being halved twice. Practical RNNs use vectors, learned maps and nonlinearities. LSTM and GRU are gated recurrent variants; their full equations are outside this chapter.

Attention provides a different route. Instead of passing all information through a chain of states, each position scores the positions it may read and mixes their information. We call the comparison vectors queries and keys, and the information to mix values. Sections 4-5 calculate each of these.

Within one layer, known input positions can have their query, key and value vectors computed together. Layer 2 still waits for layer 1, and ordinary generation still waits for each unknown next token. Direct connections can help with distant relationships, but do not guarantee accuracy at every context length.

The 2017 Attention Is All You Need paper introduced an encoder-decoder Transformer for tasks such as translation. An encoder builds source-sequence states using self-attention and a feed-forward network. Its decoder has causal target self-attention, cross-attention to those source states, and a feed-forward network. Residual additions and normalization accompany the sublayers. The original six-layer stacks are historical settings, not requirements. "Identical layers" means the same structural pattern, not necessarily tied parameter values.

Predict / Two sequences or one?

A translation model has four source tokens and has generated two target tokens. Which sequence supplies a decoder cross-attention query, and which supplies its keys? Does an RNN's fourth toy input x4=0 wait for h3?

Reveal solution

The decoder's target state supplies the query; the four encoder source states supply keys and values. Source and target lengths need not match. The recurrence must use h3=1.5, so h4=0+0.5(1.5)=0.75. A causal Transformer can process known target positions together during training, but cannot know a not-yet-selected target token during ordinary generation.

2. Give every axis and operation a meaning

A scalar is one number, a vector is an ordered coordinate list, and a matrix is a rectangular table. A tensor is an array that can have more than two axes. An axis identifies what varies as you move through the array; its size tells you how many entries are available along that direction.

For example, shape [B,N,d] means B examples, N token positions per example, and d feature coordinates per position. With shape [2,3,4], choose one of two examples, then one of its three positions, then one of that position's four coordinates to locate a number. These are counts, not token IDs. We omit the batch axis when calculating one example. Chapter 1 teaches matrix shapes.

Use one row per token throughout this chapter. X has shape N-by-d. Xij means coordinate j at token position i: i runs from 1 through N, and j from 1 through d.

Earlier chapters drew individual vectors as columns. To perform the same map on rows, transpose the weight matrix too; do not copy the column-form weights without changing their layout. A superscript T means transpose: swap rows and columns, not take an inverse. Row-oriented XW needs W's number of rows to match X's number of columns.

The capital sigma means sum: multiply matching entries, then add as r runs through all input coordinates. Here i selects a token row and j an output coordinate. W has d rows and as many columns as the output width, which can differ from d. For input row [2,1] and weight column [3,-1], the result is 2(3)+1(-1)=6-1=5.

We call this learned matrix map a projection; it need not be a perpendicular geometric projection. A linear map combines weighted inputs and sends all-zero input to zero. An affine map also adds a constant offset, or bias. A nonzero bias makes the map affine, even if a framework calls it linear.

We will also need three calculator operations. An exponential, exp⁡(z)=ez\exp(z)=e^zexp(z)=ez, extends repeated multiplication to real inputs. The constant e is approximately 2.71828. The result is always positive for finite real z, with e0=1e^0=1e0=1 and e−z=1/eze^{-z}=1/e^ze−z=1/ez.

The natural logarithm ln(a) reverses exponentiation: it answers, "What power of e gives a?" Its input a must be positive. For example, exp(ln3)=3 and ln1=0.

The square root of a nonnegative number a is the nonnegative number whose square equals a. The square root of 4 is 2 because 2(2)=4. We round calculator values only when displaying them. Chapter 2 gives the fuller function lesson.

3. IDs choose rows; position and context change states

A tokenizer turns text into vocabulary IDs using a checkpoint-specific contract. A checkpoint is saved model parameters and their configuration. Tokens need not be whole words; chapter 3 separates characters, bytes, tokens and IDs. For this deliberately invented tokenizer, use vocabulary IDs 0="queue", 1="job", 2="<end>". The text "queue job" becomes [0,1]. These are addresses, not semantic magnitudes.

Worked example / Two lookups and two additions

Choose Vocab=3, d=2. The learned table E has rows [0.8,0], [0,0.8], [0.1,0.1]. IDs 0 and 1 select the first two rows, producing a 2-by-2 table, not the full 3-by-2 vocabulary table. Choose learned position rows P1=[0.2,0] and P2=[0,0.2]. Add matching coordinates:

X=[0.8+0.20+00+00.8+0.2]=[1001]X=\begin{bmatrix}0.8+0.2&0+0\\0+0&0.8+0.2\end{bmatrix}=\begin{bmatrix}1&0\\0&1\end{bmatrix}X=[0.8+0.20+0​0+00.8+0.2​]=[10​01​]

Token count and width remain 2. If ID 0 occurred at position 2, its input would be [0.8+0,0+0.2]=[0.8,0.2], despite selecting the same learned token row. Training can change E and P; a new request changes selected rows and computed states without ordinarily updating the parameters.

Position information gives the computation a way to distinguish where tokens occur. Without position information or masking, full content-only self-attention treats rearranged rows the same way: move an input row, and its output row moves with it. This property is called permutation equivariance. It does not mean that the ordered output stays unchanged.

A causal mask already makes access depend on order: later positions can read more of the prefix. But an access rule is not the same as a rich position representation. Chapter 4 demonstrates the difference. Learned additive positions, sinusoidal additive positions and rotary positions are alternatives, not three steps every model must perform together.

RoPE, rotary position embeddings, ordinarily rotates pairs of query and key coordinates rather than adding P to X. We will label the query and key tables Q and K in section 4. Recall chapter 4's rotation lesson: a quarter-turn sends [a,b] to [-b,a].

Start with q=k=[1,0]. Their dot product is 1(1)+0(0)=1. Rotate both by a quarter-turn: [0,1] dot [0,1]=0+1=1. Rotate only the key: [1,0] dot [0,1]=0. Rotating both equally keeps the comparison unchanged; rotating them differently can change it. This lets relative position affect attention scores. Real RoPE uses specified rotation rates on multiple coordinate pairs, with values normally unrotated. Our main example has only one query/key coordinate per head, so it cannot rotate a pair. It uses additive positions instead.

Predict / Three different controls

If "job" moves to position 1, what is its additive input? Does moving it change E? Does a quarter-turn authorize access to future tokens?

Reveal solution

ID 1 still selects [0,0.8], and P1 adds [0.2,0], giving [0.2,0.8]. The stored E is unchanged. Rotation supplies position-dependent comparisons; it does not decide whether a key is allowed. A separate mask enforces that boundary. Being able to calculate more positions also does not establish reliable quality beyond a model's evaluated context range.

4. Queries compare; values carry the mixture

One attention head performs one set of comparisons and mixtures. Its query describes what a position is comparing for. A key is what a candidate position offers for comparison. The associated value is the information that candidate contributes to the mixture.

All three are numerical vectors calculated with learned weight matrices. The search analogy explains their roles, not their contents: queries are not literal search strings, keys are not indexed documents, and matching them does not verify truth.

Q=XWQ,K=XWK,V=XWVQ=XW_Q,\qquad K=XW_K,\qquad V=XW_VQ=XWQ​,K=XWK​,V=XWV​

For one head, WQ and WK have shape d-by-dk, and WV has shape d-by-dv. Multiplying X by each matrix gives one result row per input position. Q and K have dk coordinates per row; V has dv. Query and key widths must match so we can multiply corresponding coordinates and add. Value width can differ because values enter a later operation. These formulas omit optional biases and position rotation. In a pre-normalized block, they receive normalized states. We first calculate the projections on the given rows; section 11 supplies the preceding normalization.

Worked example / Derive head A, not just its result

Take section 3's two rows [1,0] and [0,1], with dk=dv=1. Head A has WQ=[1,1]T, WK=[0,ln3]T and WV=[2,4]T, each shape 2-by-1. First-row products give q1=1(1)+0(1)=1, k1=1(0)+0(ln3)=0 and v1=1(2)+0(4)=2. Second-row products give q2=0(1)+1(1)=1, k2=0(0)+1(ln3)=ln3 and v2=0(2)+1(4)=4.

Thus Q=[1,1]T, K=[0,ln3]T, V=[2,4]T. The parameters are the projection entries; these six outputs are input-dependent activations. The particular ln3 coefficient was chosen to make the later softmax arithmetic exact, not learned from text.

5. Score, scale, mask, normalize, then mix

A dot product multiplies corresponding coordinates and adds them; chapter 1 gives its geometry. Each query needs a score for every candidate key. Transpose K so its key rows become columns, then multiply QKTQK^TQKT. The shapes are (N-by-dk) times (dk-by-N), giving an N-by-N score table. Row i contains query i's scores; column j corresponds to key j.

Divide each dot-product score by the square root of the query/key width dk. We will explain why after the first calculation. Then restrict access. A causal mask permits j at most i: a position can read itself and earlier positions. This is safe because its state predicts the next token, not its own input token. A padding mask instead excludes placeholder positions used to make input lengths match. Padding and causality solve different problems.

sij is query i's scaled, masked score for key j. The index r runs over query/key coordinates. M is the mask: add 0 for an allowed key and negative infinity for a blocked future key. This piecewise notation means choose the case whose condition is true.

Negative infinity is an exclusion rule, not an ordinary stored input value. As a score falls without bound, its exponential approaches zero, so a blocked key contributes nothing to the softmax sum. Code may use explicit masking or a supported special value. Mask before normalizing: setting a finished probability to zero leaves the old denominator in place. Each evaluated row needs at least one permitted key; an all-blocked row requires separate handling to avoid division by zero.

Softmax turns one score row into nonnegative weights summing to one. Exponentiation makes finite scores positive; division by their sum sets the total to one. It compares entries within that row, not all rows together. Probability describes a distribution over specified alternatives; attention weights are mixture weights over permitted positions, not vocabulary-token probabilities or factual confidence.

These nonnegative weights sum to one, so the result is a convex mixture. Each output coordinate lies between the smallest and largest corresponding permitted value coordinates. Once the weights are known, mixing is a matrix multiplication. The full attention operation is still nonlinear: changing the input also changes the scores and weights used in that multiplication.

Worked example / All four scores, then both output rows

Head A's raw score products are q1k1=1(0)=0, q1k2=1(ln3)=ln3, q2k1=1(0)=0 and q2k2=1(ln3)=ln3. With dk=1, the divisor is 1, so scaling changes nothing. The causal mask gives rows [0,-infinity] and [0,ln3].

Row 1 has exponential entries [1,0], sum 1 and weights [1,0]. Its output is 1(2)+0(4)=2. Row 2 has exponentials [1,3], sum 4 and weights [1/4,3/4]. Its output is (1/4)(2)+(3/4)(4)=0.5+3=3.5. Output shape is 2-by-1. Without the mask, row 1 would also give 3.5 and would improperly use the second token while predicting it.

Why divide by a square root?

A dot product adds one product per coordinate. More terms can produce a wider spread of scores, even when each term has a modest size. We divide by a square root to control that spread, not to make the scores sum to one. Softmax later turns the scores into weights that sum to one.

First make spread measurable. A mean is sum divided by count. Variance is the mean of squared differences from that mean; standard deviation is its nonnegative square root. For equally likely outcomes [-1,1], the mean is (-1+1)/2=0 and variance is (1+1)/2=1.

Independent choices do not influence one another's probabilities. Adding two independent choices from [-1,1] gives four equally likely sums [-2,0,0,2]. Their mean is zero, but their variance is (4+0+0+4)/4=2. Divide each sum by square root of 2. Each squared deviation is then divided by 2, bringing variance back to 1.

If query/key coordinates are approximately independent, centered (mean zero) and unit-variance, each product has variance about one, and a sum of dk such products has variance about dk. Dividing scores by square root of dk brings that approximate standard deviation back toward one. This is initialization-scale reasoning under stated assumptions, not a guarantee for arbitrary learned vectors. Section 8 applies these same statistical operations within a token.

Worked example / A nontrivial divisor

For a separate width-two head, choose q=[2,0], keys [1,1] and [0,1]. Raw scores are 2(1)+0(1)=2 and 2(0)+0(1)=0. Divide by square root of 2, approximately 1.414214: scaled scores are approximately [1.414214,0]. Their exponentials are approximately [4.113250,1], sum 5.113250, giving weights approximately [0.804430,0.195570]. With values [1,2] and [3,0], the first coordinate is 0.804430(1)+0.195570(3), approximately 1.391141; the second is 0.804430(2)+0.195570(0), approximately 1.608859.

Without scaling, scores [2,0] give weights approximately [0.880797,0.119203]. Still larger differences, such as [10,0], give approximately [0.999955,0.000045]. This concentration is called softmax saturation. A derivative measures local output change per small input change. Holding other scores fixed, a weight a has sensitivity a(1-a) to its own score; chapter 2 derives this. At a=0.5, calculate 0.5(1-0.5)=0.25; near a=0.999955, calculate 0.999955(0.000045), approximately 0.000045. Scaling helps control this effect; it does not force equal weights.

For numerical stability, subtract a row's largest permitted score before exponentiating. This leaves ratios unchanged because every exponential is divided by the same factor. For [0,ln3], shift by ln3: exponentials become [1/3,1], sum 4/3, and weights remain [(1/3)/(4/3),1/(4/3)]=[1/4,3/4]. Do not exponentiate huge scores unnecessarily.

Predict / A mask is not a position vector

For head A's first row, someone computes unmasked weights [1/4,3/4], then discards the second value and returns 0.5. Repair the result. For row 2, if both keys equal zero but values stay [2,4], what is the output?

Reveal solution

Exclude the future key before normalization. The remaining exponential is 1 and denominator is 1, so weight 1 returns 2, not 0.5. With two equal permitted scores, each exponential is 1, denominator 2, weights [1/2,1/2], and output 1+2=3. Position mechanisms alter comparisons; the mask alters access; the softmax normalizer depends on the surviving positions.

6. Derive another head, then concatenate and project

A head is one set of projected query/key comparisons and value mixtures. Multi-head attention runs several sets, then combines their outputs. Different parameters can support different relationships, but no head is assigned a permanent "grammar" or "facts" job. Several heads do not guarantee interpretable specialization.

Worked example / Head B on the same two rows

Choose WQ=[1,-1]T, WK=[ln3,0]T, WV=[1,5]T. For [1,0], query is 1(1)+0(-1)=1, key is 1(ln3)+0(0)=ln3, value is 1(1)+0(5)=1. For [0,1], query is 0(1)+1(-1)=-1, key is 0(ln3)+1(0)=0, value is 0(1)+1(5)=5.

At dk=1, scaled scores before masking are rows [ln3,0] and [-ln3,0]. Row 1 can only use its own key, so weights [1,0] give output 1. Row 2 exponentials are [1/3,1], sum 4/3, weights [1/4,3/4]. Its output is (1/4)(1)+(3/4)(5)=0.25+3.75=4. Thus the two heads return columns [2,3.5]T and [1,4]T.

Concatenation joins coordinate lists; it is not addition. At each position, concatenate A then B, producing rows [2,1] and [3.5,4]. The joined width is Hq times dv. A learned output matrix WO has shape (Hq dv)-by-d and restores model width; it need not simply average the heads.

Omit batch for one example with two positions, two heads and two coordinates per head. Suppose fused rows are [10,11,20,21] and [12,13,22,23]. Head outputs at one position are [1,2] and [3,4]. What does concatenation produce? If d=1,024 and there are 32 equal-sized query heads, what is dk?

7. Cross-attention changes where the keys come from

Self-attention derives Q, K and V from the same sequence's states. Cross-attention derives Q from a target sequence and K/V from a separate source. In an encoder-decoder, the encoder output is already contextual, not a dictionary table. Each decoder layer can have its own cross-attention projections.

Q=DWQ,K=SWK,V=SWVQ=DW_Q,\qquad K=SW_K,\qquad V=SW_VQ=DWQ​,K=SWK​,V=SWV​

D is the target-state table, length Nt and width dt. S is the source-state table, length Ns and width ds. WQ is dt-by-dk, WK is ds-by-dk, and WV is ds-by-dv. Scores have shape Nt-by-Ns, not necessarily square. Encoder-decoder target self-attention is causal; cross-attention normally permits the entire available nonpadding source, because those input tokens are already known.

Worked example / One target query, three source values

Let D=[1,0], S rows [1,0], [0,1], [1,1]. Choose WQ=[1,0]T, WK=[0,ln2]T and WV with rows [2,0], [0,3]. Then q=1(1)+0(0)=1; keys are 0, ln2, and ln2. Value products give [2,0], [0,3], and [2,3]. For the third source row, for example, the first value coordinate is 1(2)+1(0)=2 and the second is 1(0)+1(3)=3.

At dk=1 and with all source keys permitted, scores [0,ln2,ln2] exponentiate to [1,2,2], sum 5. Weights are [1/5,2/5,2/5]. The first output coordinate is (1/5)(2)+(2/5)(0)+(2/5)(2)=0.4+0+0.8=1.2. The second is (1/5)(0)+(2/5)(3)+(2/5)(3)=0+1.2+1.2=2.4. Score shape is 1-by-3; output shape is 1-by-2.

Predict / A padded source row

If the third source row is padding, recompute the mixture rather than removing its old weighted contribution. Does this add cross-attention to every decoder-only model?

Reveal solution

Only exponentials [1,2] remain, sum 3, so weights are [1/3,2/3]. Output is [(1/3)(2)+(2/3)(0),(1/3)(0)+(2/3)(3)]=[2/3,2]. Decoder-only self-attention over an injected document is still self-attention over one combined prefix. Separate source keys/values require an architecture that actually has cross-attention.

8. Normalize features without turning them into probabilities

The size and center of activations can change as they pass through layers. LayerNorm adjusts their scale using the features within each token row, not neighboring tokens. It first subtracts the row's center and divides by a spread scale. Then it applies learned scales and shifts to the coordinates.

To find the center, add the coordinates and divide by their count: this is the mean. Subtract it from each entry to get deviations. Square the deviations and average them to get the variance. Squaring prevents positive and negative deviations from canceling. Here the average divides by the full width d, not d-1.

9. Add a direct route, and say where normalization goes

A residual connection gives a representation a direct route around a transformation. Split the input into two paths: one goes through the branch, and one bypasses it. Add their results coordinate by coordinate. The shapes must match, and the output keeps the same width. This is addition, not concatenation; the sum does not contain a separately stored original copy.

For the first toy token, input [1,0] plus section 6's attention result [3,1] gives [4,1]. For the second, [0,1]+[7.5,-0.5]=[7.5,0.5]. Call this residual table R. We are isolating the addition here; section 11 supplies the normalization that precedes the attention branch.

y=x+F(x)\mathbf{y}=\mathbf{x}+F(\mathbf{x})y=x+F(x)

F names the branch function. An attention branch also reads other permitted rows, even though this compact notation shows one token's result.

The direct route matters during backpropagation too. For a scalar example, let F(x)=0.1x. The direct path has rate 1 and the branch has rate 0.1, so output sensitivity to x is 1+0.1=1.1. If loss sensitivity to the output is 2, the two backward contributions are 2(1)=2 and 2(0.1)=0.2. Add them to get 2.2. Without the skip, only 0.2 would reach x in this example. See the chain rule and branch sums.

This extra path can help gradients reach earlier layers. It does not guarantee preservation: F(x)=-x would cancel both the output and its sensitivity.

Where does normalization go? In Pre-Norm, normalize only the branch input, then transform it and add the original input. The skip bypasses both normalization and transformation. In Post-Norm, transform the input, add the skip, and normalize the sum. Write out the order before comparing the formulas:

Pre: x+F(LN⁡(x))\text{Pre: }\mathbf{x}+F(\operatorname{LN}(\mathbf{x}))Pre: x+F(LN(x))
Post: LN⁡(x+F(x))\text{Post: }\operatorname{LN}(\mathbf{x}+F(\mathbf{x}))Post: LN(x+F(x))

Worked example / Order changes the numbers

To isolate order, let F return the constant row [1,0], input x=[1,3], unit gamma, zero beta and epsilon=0.00001. Pre-Norm's residual result is [1+1,3+0]=[2,3]. Post-Norm normalizes that sum: mean 2.5, deviations [-0.5,0.5], squares [0.25,0.25], variance 0.25 and denominator approximately 0.500010. Its output is approximately [-0.999980,0.999980]. Recognize a gate without assuming every FFN uses it

GELU multiplies z by a smooth gate Phi(z), the standard-normal cumulative probability at z. Chapter 5 defines that probability model: Phi(1) is approximately 0.841345, so GELU(1)=0.841345, Phi(-1)=1-0.841345=0.158655 and GELU(-1)=-0.158655. It is deterministic, not a random draw at each call.

SwiGLU is a gated FFN variation. Two projections read the same input row: an up branch produces features, and a gate branch produces multipliers for those features. Multiply matching coordinates, then use a down projection to return to model width.

14. Separate architectural changes from execution algorithms

MHA, GQA and MQA change key/value sharing

The next three variations answer different questions: which heads share keys and values, which feature-transform networks run for a token, and how attention uses memory during execution. Keep those jobs separate as we work through each example.

Ordinary multi-head attention (MHA) gives each query head its own key and value head. Grouped-query attention (GQA) lets several query heads reuse one key/value head. Multi-query attention (MQA) uses one key/value head for all query heads.

Sharing means fewer KV projections and fewer cached numbers. Queries still stay separate: each query computes its own scores, weights and output from the shared keys and values. The model must be built and trained for this sharing; it is not a cache setting you can switch on for an arbitrary checkpoint.

MoE chooses which feature-transform networks run

A mixture of experts (MoE) uses several expert networks in place of a single dense FFN. A learned router scores the experts for each token and selects which ones to run. This is different from attention heads. Attention heads mix information across positions; experts perform feature transformations after routing. Attention and other shared model components still run. Selecting two experts reduces expert work for that token, but the other experts still need to be stored or made available.

Worked example / Specify the routing rule

Take row x=[1,2]. Stipulate router logits [ln3,ln2,0], whose softmax exponentials [3,2,1] sum to 6, giving [1/2,1/3,1/6]. Choose the two largest, then renormalize their weights: retained sum is 1/2+1/3=5/6; weights are (1/2)/(5/6)=3/5 and (1/3)/(5/6)=2/5.

To expose arithmetic, use simplified affine experts F1(x)=[x1,x2+1] and F2(x)=[2x2,0], rather than pretending to derive full production FFNs. F1([1,2])=[1,3], F2([1,2])=[4,0]. The weighted output is [(3/5)(1)+(2/5)(4),(3/5)(3)+(2/5)(0)]=[0.6+1.6,1.8+0]=[2.2,1.8]. Other routing/weight conventions exist; this exact top-two renormalization is our stipulation.

Suppose there are eight experts with 100 stored parameters each, and the router selects two per token. Total expert storage is 8(100)=800 parameters. The selected experts use 2(100)=200 parameter entries for that token. These counts exclude the router, shared components, activations and communication.

Running only some experts is called sparse expert evaluation. It can provide more total parameter capacity without running every expert for every token. The tradeoff is routing and storage overhead. Uneven selection can overload one expert, and experts on different devices must exchange data. An optional always-active shared expert adds work too. These counts do not predict a real model's quality or speed.

FlashAttention changes how the same attention is evaluated

Ordinary attention can create large score and weight tables. Writing those tables to GPU memory, then reading them back, costs time and space. FlashAttention changes that execution plan, not which heads share KV data or which keys are permitted.

It is IO-aware: it is designed to reduce data movement between memory levels. A tile is a small block of entries processed together. The algorithm works on tiles in faster local storage and updates running sums instead of writing the full score and weight tables to larger GPU memory.

The result is exact attention in mathematical arithmetic, with possible floating-point differences from a different calculation order. Tiling does not discard distant keys, select experts or approximate softmax. Every permitted query-key comparison still contributes.

Worked algorithm bridge / A one-row streaming normalizer

Recover head A's second-row result while processing one score/value pair at a time. We need the sum of exponentials for the denominator and the sum of exponential-times-value terms for the numerator. We can divide at the end, so we do not need to keep each finished weight.

To keep exponentials small, measure both sums relative to the largest score seen so far, m. Call the denominator sum l and the numerator sum z. For the first score 0 and value 2, m=0, l=exp(0-0)=1, and z=1(2)=2.

The next score is ln3 with value 4. The new maximum is m'=ln3. The old sums used maximum 0, so convert them to the new scale: multiply both by exp(m-m')=exp(-ln3)=1/3. The new term has exponential exp(ln3-m')=1.

Now add the new contributions: l'=(1/3)(1)+1=4/3 and z'=(1/3)(2)+1(4)=2/3+4=14/3. Divide the final numerator by the final denominator: z'/l'=(14/3)/(4/3)=14/4=3.5. Rescaling both sums preserves their ratio, so this matches the earlier attention result.

This scalar demonstration explains stable accumulation; it is not a production GPU kernel or all FlashAttention scheduling details. For vector values, z stores one accumulated sum per value coordinate. A newly larger maximum rescales every old sum consistently. Real implementations tile multiple queries/keys, handle masks and gradients, and use architecture-specific kernels. Their changed accumulation order can change low-order floating-point bits. Reduced intermediate storage does not erase full-attention's quadratic pair count.

Start with the first permitted pair: m=s, l=1, z=v. Apply the update to later pairs, then divide z by l. At least one pair must be permitted. Predict / Three kinds of efficiency

Does GQA reduce the number of query outputs? Does MoE store only the selected experts? If the two equal FlashAttention bridge scores are 0 and 0 with values 2 and 4, calculate the accumulators and output.

Reveal solution

GQA shares KV heads but preserves separate query-head outputs. MoE must store or otherwise make its expert parameters available; selecting a subset reduces per-token expert computation, not automatically total resident storage. After the first score, m=0, l=1, z=2. The second leaves m=0 and adds exponential 1: l=2, z=2+4=6, output 6/2=3. These changes respectively concern KV representation, routed feature computation, and memory-efficient execution of attention; they are not the same optimization.

15. The serving engine executes; the application supplies a contract

Calling a model API delegates numerical execution, not responsibility for the request. The application constructs messages, history, tool results and retrieved context. The serving engine encodes them using the required format, runs the model, manages caches and sampling, and returns generated tokens. Chapter 3 separates role/control tokens from visible prose; chapter 4 separates retrieval vectors from the actual text supplied to a model.

Two lanes of one request
Application responsibilityModel/serving responsibility
Select authorized evidence and construct messagesApply tokenizer, template and input/mask conventions

Validate tool actions, enforce permissions, handle cancellationManage compatible KV state and next-token selection
Display streaming output and evaluate resultsDecode/stream generated token pieces under the response protocol

Hidden states may encode learned role distinctions when the format includes them, but neither attention weights nor control tokens are an authorization mechanism. A retrieved paragraph can contain hostile instructions; it does not become trusted because it was close in embedding space. Preserve boundaries and enforce policy outside the model as needed. A token chunk also need not equal a complete word or a complete validated tool command.

Worked engineering check / Reserve the continuation

For a hypothetical 100-token context allowance, messages/format use 12 tokens, evidence uses 45 and conversation uses 23. Used input is 12+45+23=80; reserving 15 generated tokens totals 95, leaving 5. Another 10-token passage would total 105 and exceed this stipulated allowance. This is an input/output budget example, not a model benchmark or a universal API accounting rule.

Prefill/decode, time to first token, inter-token latency, batching, throughput, quantization and GPU serving require separate implementation lessons. This chapter teaches basic causal cache reuse and payload arithmetic, not complete serving algorithms or measured latency. Adding more blocks likewise adds parameters/compute and optimization demands, not an automatic guarantee of improved quality.

Predict / What must the application still decide?

Can a highly weighted retrieved passage authorize a database write? With the budget above, can you add a ten-token passage while retaining the same output reservation?

Reveal solution

No. Attention scores describe numerical mixing, not permission, provenance or reliable truth. Authorization and validation remain explicit system duties. The added passage would bring the reserved total from 95 to 105, above 100; shorten permitted content or change the reservation under the actual model/API contract. Do not silently truncate evidence and claim the same request was processed.

16. Interview questions

Use these 20 prompts to practice the architecture, calculations, and implementation tradeoffs. Explain the reasoning before memorizing the component names; the answers link back to the worked lessons.

01 / What makes a Transformer a sequence architecture?

Explain the answer

It composes attention-based exchange with feature transformations, usually wrapped in normalization and residual additions. Head A's query at position 2 scores keys [0,ln3], normalizes [1,3] to [1/4,3/4], and mixes values [2,4] to 3.5. That calculation makes the state depend on other permitted positions. Unlike a recurrent state chain, known input positions' projections within a layer can run together. Generation and successive layers still have dependencies. Review the architecture paths.

02 / Which components belong to the original model and to a decoder-only model?

Explain the answer

The original encoder has self-attention and an FFN; its decoder adds causal target self-attention and source cross-attention before its FFN. Residual/norm operations accompany the sublayers. Our decoder-only program instead uses lookup/position, repeated causal attention plus FFN blocks, final normalization, vocabulary projection and selection. Removing the encoder does not leave an invisible cross-attention source. In our trace, two-by-two hidden rows become two-by-three logits, not three new token rows. Compare families and trace the complete model.

03 / Why did attention help replace recurrence in many language workloads?

Explain the answer

Known position projections and comparisons can be batched within a layer, and attention provides direct paths between permitted distant positions rather than repeatedly passing through intervening recurrent states. In h_t=x_t+0.5h_(t-1), inputs [2,0,1] require states 2, then 1, then 1.5 in order; the earliest contribution is repeatedly scaled. That toy fading path illustrates a dependency, not a proof that every RNN fails. Accelerator-friendly matrix operations helped scaling, while long-context attention has its own quadratic comparison cost. Neither model quality nor sequential-generation removal follows automatically. Review the dependency calculation.

04 / How do the three architecture families differ?

Explain the answer

An encoder-only model usually builds states from full nonpadding input context; a task head can use them for classification or trained representations. A decoder-only model causally predicts a continuation. An encoder-decoder conditions a causal target decoder on separate encoded source states. For four source positions and two target positions, cross scores can be 2-by-4 while target self-scores are 2-by-2. BERT, GPT-style and T5 are illustrative families, not a guarantee of every vendor's hidden implementation. Review the comparison.

05 / What is repeated when a model stacks Transformer blocks?

Explain the answer

A structural unit transforms incoming hidden states through attention and FFN branches with residuals and normalization. In our Pre-Norm trace, R=X+A(LN1(X)), then Y=R+FFN(LN2(R)). The first row moves [1,0] to [4,1], then approximately [6,2]; model width stays two. A second block receives Y, not the original token lookup again. Repeated structural pattern does not mean all blocks share weights. Norm placement and branch variants must be specified. Review all intermediate values.

06 / How does self-attention make one position contextual?

Explain the answer

Q, K and V come from the same sequence's current states. Query/key dot products are scaled, masked and row-normalized; weights combine value coordinates. With q=1, keys [0,ln3] and values [2,4], permitted scores exponentiate to [1,3], sum 4, weights [1/4,3/4] and output 0.5+3=3.5. It is not direct multiplication of token IDs or a dictionary sense lookup. Those weights are input-dependent numerical routing, not a verified explanation of truth. Review the projections and the mixture.

07 / What changes in cross-attention?

Explain the answer

The query comes from the target state table, keys/values from another source table. Shared key/query coordinate width allows comparison even when sequence lengths differ. Our one target query against three source keys produces scores [0,ln2,ln2], weights [1/5,2/5,2/5], and values [2,0], [0,3], [2,3] mix to [1.2,2.4]. Target self-attention remains separately causal; source cross-attention can use the full available source with padding excluded. Injecting a document into one decoder prefix does not by itself create a cross-attention module. Review both source contracts.

08 / What do several heads add, and how are they combined?

Explain the answer

Separate learned projections permit different comparisons and value mixtures. At our second position A returns 3.5 and B returns 4; concatenate to [3.5,4], then multiply WO to obtain [3.5+4,3.5-4]=[7.5,-0.5]. Concatenation is not averaging or addition, and head outputs do not run through each other. Multiple heads increase representational options without assigning guaranteed semantic roles. If Hq=2 and dv=1, joined width is 2; WO maps that width back to d. Review both complete heads.

09 / Why scale the query-key dot product?

Explain the answer

With approximately independent centered unit-variance coordinates, the sum of dk query-key products has variance about dk and standard deviation about its square root. Dividing by that square root controls typical initialization score scale. For dk=2, a raw score 2 becomes approximately 1.414214; against score zero its softmax weight is approximately 0.804430 rather than 0.880797. Large score differences can saturate weights and reduce local derivatives. This is assumption-dependent scale reasoning, not a bound on all trained scores or a command to divide by model width. Review assumptions and arithmetic.

10 / What exactly does a causal mask prevent?

Explain the answer

Query row i cannot use keys at positions j greater than i. It may use its own token because that row predicts token i+1. In [queue,job], row 1's target is job, so its weights must be [1,0]; head A returns 2 instead of the unmasked 3.5. Mask before normalization; dropping an old weighted term gives the wrong denominator. A position vector or query/key rotation does not enforce this access rule, and a padding mask has a different purpose. Review the table and shifted labels.

11 / How do residual connections help, and what do they not guarantee?

Explain the answer

They add a matching-width input directly to a transformed branch. [1,0]+[3,1]=[4,1] preserves width, not a separately stored original row. With scalar branch F(x)=0.1x, output derivative is 1+0.1=1.1; incoming loss sensitivity 2 becomes 2.2 rather than 0.2 through the branch alone. This direct gradient route can aid optimization. F(x)=-x cancels the result and derivative, so neither information preservation nor successful training is guaranteed. Review the skip arrows and shape condition.

12 / What does LayerNorm normalize?

Explain the answer

For each token separately, it subtracts the mean across feature coordinates, divides by square root of variance plus positive epsilon, then applies learned feature scales/shifts. Row [1,3] has mean 2, deviations [-1,1] and variance 1; unit-scale zero-shift output is approximately [-0.999995,0.999995] at epsilon 0.00001. Another token has its own statistics. This controls activation statistics rather than creating probabilities or averaging the sequence. RMSNorm instead divides by a root mean square without centering; the same row becomes approximately [0.447213,1.341639]. Review both ledgers.

13 / Why is Pre-Norm different from Post-Norm?

Explain the answer

Pre-Norm computes x+F(LN(x)); Post-Norm computes LN(x+F(x)). The first preserves an unnormalized skip route around the normalized branch, while the second normalizes the sum. With x=[1,3] and constant F=[1,0], Pre gives [2,3]; Post centers/rescales [2,3] to approximately [-0.999980,0.999980]. These numbers demonstrate noninterchangeable order. Many deep modern designs use Pre-Norm for optimization behavior, but it is not a universal specification or a stability guarantee. Review the exact convention.

14 / What does an FFN do that attention does not?

Explain the answer

The position-wise FFN transforms the current row's features through learned maps and nonlinearities. Our [1,-1] expands to [1,-1,2], ReLU gives [1,0,2], and contraction produces [2,1]. It does not directly compare neighboring token rows. Attention mixes positions, but is itself also a nonlinear input-dependent operation; saying it is only a fixed average would be misleading. A common FFN expands features then returns to model width for the residual, with shared parameters across positions. GELU or gated variants are architecture choices. Review feature and gate calculations.

15 / Why does the model need a language-model head?

Explain the answer

Hidden feature coordinates are not vocabulary scores. A Vocab-by-d matrix U maps a row h to hUT, producing Vocab logits. In our width-two example h=[u,-u] and output rows [ln2,0], [0,0], [0,ln2] give [u ln2,0,-u ln2], three candidate scores. Tied embeddings can reuse an input matrix but are not mandatory. The head changes feature width, not sequence length, and softmax/selection remain separate operations. Review the complete final projection.

16 / What distinguishes a logit from a probability?

Explain the answer

A logit is an unnormalized real score, which can be negative and need not sum to anything. Softmax of [ln2,0,0] exponentiates to [2,1,1], sum 4, and divides to [0.5,0.25,0.25]. Adding the same score offset leaves the distribution unchanged because it multiplies every exponential by one common factor. A normalized prediction distribution is not a claim that generated content is true. Attention softmax distributes weights over positions; a language head's softmax distributes probability over vocabulary IDs. Review row normalization.

17 / How does grouped-query attention reduce cache payload?

Explain the answer

Several distinct query heads reuse a KV head. At fixed B,L,N,dk,dv and stored precision, cache payload follows Hkv rather than Hq. Our four-query MHA example needs 192 bytes; two-KV GQA needs 96; one-KV MQA needs 48. Shared keys [0,ln3] with values [2,4] still give q=1 output 3.5 and q=-1 output 2.5, so sharing does not force identical queries or answers. Payload reduction is not a measured speed/quality guarantee or a runtime replacement for training-compatible projections. Review grouping and counts.

18 / What is sparse about a mixture of experts?

Explain the answer

A router chooses a subset of expert feature-transform networks per token. Our router probabilities [1/2,1/3,1/6] select the first two; renormalizing gives [3/5,2/5]. Their outputs [1,3] and [4,0] combine to [2.2,1.8]. Sparse expert evaluation can increase total parameter capacity relative to active per-token work, but the router and shared attention still run. Unselected experts still require storage/availability, and load balance/communication can be expensive. Actual experts are not necessarily interpretable topic specialists, and shared-expert variants exist. Review the stipulated router.

19 / Is FlashAttention approximate or a different attention architecture?

Explain the answer

It is an IO-aware execution algorithm for exact attention in mathematical arithmetic, subject to floating-point differences, not a sparse-key selection architecture. Tiling avoids writing full intermediate score/weight matrices to larger memory. Our streaming row maintains scaled sums: first m=0,l=1,z=2; after score ln3/value 4, m=ln3,l=4/3,z=14/3, so z/l=3.5 matches ordinary softmax attention. Full permitted comparison count remains; memory traffic and intermediate storage are the target. Review stable rescaling.

20 / Why does ordinary autoregressive generation remain sequential?

Explain the answer

The selected next token becomes context for the following prediction. With prefix [queue,job], our model selects queue, then the next pass receives [queue,job,queue]; it could not know that third ID before selection. Training can batch known shifted targets under a causal mask, and cache reuse avoids recomputing valid old keys/values, but neither supplies unknown future tokens. Execution can parallelize heads, coordinates and independent requests; that is different from removing this within-sequence dependency. Detailed alternative decoding engines are deferred. Review the axes of dependency.

17. Reconstruct the flow, then identify the tradeoff

The durable mental model

  • IDs address learned rows. Position mechanisms and context-dependent computation change states, not dictionary meanings.
  • Queries and keys calculate permitted weights; values supply the coordinates mixed. Heads have separate projections and a combined output map.
  • Residuals add matching shapes; normalization compares features; FFNs transform each current row. Their order and variants matter.
  • The language head makes vocabulary scores. A prediction target drives training; selecting and appending a token drives ordinary generation.
  • GQA changes KV sharing, MoE changes expert activation, and FlashAttention changes memory-efficient evaluation. None is a universal quality or speed guarantee.

Synthesis / Audit a model diagram

A hypothetical model has B=1, N=4, d=8, four query heads, two KV heads, dk=dv=2 and vocabulary size 10. Give the score shape and entry count; give all-position logits shape. If N doubles, which count quadruples? Why does adding more blocks not prove quality improves?

Reveal solution

There are four query heads despite only two KV heads, so score shape is [1,4,4,4], with 1(4)(4)(4)=64 entries in a full square. Logits are [1,4,10], 40 scores. At N=8, full scores are [1,4,8,8], 256 entries, four times 64; logits are 80, twice 40. Cache payload likewise doubles if other axes remain fixed. More blocks increase transformation depth, parameter storage and work; optimization, data quality and evaluation determine whether that capacity helps. A box count is not an accuracy metric.
