Attention in Action: How Models Select and Combine Context

Calculate every query's mixture, follow its gradients, and distinguish changes to information access from changes to cache storage and execution.

Prerequisite: chapters 01-06, refreshed at point of use15 sectionsOriginal diagrams + explained numerical experiments

The engineering question

You inspect an attention implementation. It produces the expected tensor shape, but does it mix the right positions, use the right denominator, and reuse only valid cached states? A plausible-looking matrix is not enough. We will make the computation small enough to audit by hand.

Chapter 6 assembled a complete decoder forward pass. Here we open the attention operation itself. Sections 1-7 establish its numerical and differentiation contracts; sections 8-12 compare access, caching and execution; section 13 turns the arithmetic into C#. The Interview questions section has ten prompts with fully explained answers.

Toy numbers, explicit contracts

All vectors, weights, widths and memory budgets here are stipulated teaching inputs, not observations of a trained model. We omit dropout, a training-time random omission/rescaling mechanism, and biases, constant offsets, unless explicitly introduced. Their detailed implementations are not needed for this arithmetic. Exact identities describe real-number arithmetic; decimals and floating-point code are approximations. No head is assigned a guaranteed grammatical role, and no calculated payload ratio is a measured speedup.

1. Separate matching information from contributed information

Suppose a code assistant sees "The worker released the lease after it expired." Useful context may relate "it" to the lease rather than the worker. This motivates contextual representations: intermediate numbers that depend on other permitted positions. It does not prove that an attention head resolves this sentence correctly.

A query supplies matching coordinates for a position gathering information. A key supplies matching coordinates for a candidate position. A value supplies coordinates to combine after matching. Think of a query, searchable metadata and document content, but stop the analogy there: these are learned numerical maps, not literal search strings, stored documents or verified facts.

Recall chapter 1's shape rules. A matrix is a table with rows and columns. Its shape counts both. A token-state matrix X has N rows, one per position, and d columns, one per feature coordinate. Entries are dimensionless toy features, not meters or token IDs. Individual vectors are columns elsewhere in this book; token tables use rows, so XW uses the transposed weight layout of a column expression Wx. We omit batch and head axes until section 6.

Q=XWQ,K=XWK,V=XWVQ=XW_Q,\qquad K=XW_K,\qquad V=XW_VQ=XWQ​,K=XWK​,V=XWV​

WQ and WK have shape d-by-dk; WV has shape d-by-dv. Q and K therefore have shape N-by-dk, while V is N-by-dv. dk and dv are positive integer widths. Query/key widths must match for comparison; value width need not equal them. The learned matrices are parameters. Q/K/V are input-dependent activations. In a pre-normalized block, X here means the normalized branch input, not necessarily the initial embedding lookup.

Matrix multiplication combines a row with each output column. Multiply corresponding entries and add: row [a,b] times column [c,e] produces ac+be. A transpose, written T as a superscript, swaps rows and columns; it is not an inverse. A dot product is this coordinate-by-coordinate multiply-and-sum comparison. Distinct query/key maps mean their score table need not be symmetric or have a constant diagonal.

A three-position numerical contract

Choose N=3 and d=dk=dv=2. Labels "worker", "lease", "expired" only identify our three invented positions; they are not a real tokenizer or interpretable feature meanings. A square root is the nonnegative number whose square returns its input: square root of 2 is approximately 1.414214. We write sqrt2 as compact prose shorthand for that number. The natural logarithm ln(a), defined for a>0, reverses the exponential exp(z)=e raised to z: exp(ln2)=2 and exp(ln3)=3. e is approximately 2.71828; exp(0)=1. For a negative exponent, exp(-z)=1/exp(z), so exp(-ln3)=1/3. Chapter 2 develops these functions.

2. Calculate all rows, not just one appealing heatmap

The score table has one row per query and one column per key. In self-attention both counts are N, so QKT is N-by-N: N-by-dk times dk-by-N. Scaling divides each dot product by square root of dk. For this first calculation all three keys are permitted. We will separately impose causality.

Query 1 compares with keys 1, 2, 3: raw products are sqrt2(ln2)+0(0)=sqrt2 ln2; sqrt2(0)+0(ln3)=0; sqrt2(ln2)+0(ln3)=sqrt2 ln2. Divide by sqrt2 to get [ln2,0,ln2].

Query 2 gives 0(ln2)+sqrt2(0)=0; 0(0)+sqrt2(ln3)=sqrt2 ln3; 0(ln2)+sqrt2(ln3)=sqrt2 ln3. Scaling gives [0,ln3,ln3].

Softmax exponentiates each permitted score, then divides each exponential by their sum. Exponentials are positive for finite real scores, making positive weights; dividing sets their total to one. It is a row operation, not a single denominator for the entire matrix.

A convex mixture has nonnegative weights totaling one. Consequently each output coordinate lies between the smallest and largest permitted value in that coordinate: our first coordinates stay between 0 and 2; second coordinates between 0 and 4. This bounds a head's mixture, not the later learned output projection, residual sum or vocabulary scores. Input-dependent weights also make the complete attention function nonlinear, not a fixed linear average.

Reveal solution

Coordinate 2 becomes (1/7)(0)+(3/7)(7)+(3/7)(4)=0+3+12/7=33/7, approximately 4.714286. Matching scores did not change, but the contributed payload did. The coordinate stays within the new permitted range 0 to 7.

3. Scaling controls a distribution, not a maximum allowed score

Why divide by square root of key width rather than key width itself? The motivation concerns statistical spread under assumptions, not a bound on trained scores. Refresh chapter 6's variance lesson: a mean is sum divided by count; a deviation is an outcome minus the mean; variance is the mean squared deviation; standard deviation is its nonnegative square root.

Independent means choosing one sign does not change the other sign's probabilities. Each sign is equally likely to be -1 or 1, with mean (-1+1)/2=0 and variance (1+1)/2=1. Their four equally likely sums have mean (-2+0+0+2)/4=0 and variance (4+0+0+4)/4=2. Divide each sum by sqrt2: every squared deviation is divided by 2, so variance becomes 2/2=1. Divide instead by 2: variance becomes 2/4=1/2.

For independent equally likely sign-valued query/key coordinates, the four possible products are [1,-1,-1,1]. Their mean is (1-1-1+1)/4=0 and variance is (1+1+1+1)/4=1. Adding independent coordinate products therefore has the same spread pattern illustrated above. More generally, if query and key coordinates are approximately independent across coordinates and from each other, centered and unit-variance, their products have variance about one and a sum of dk products has variance about dk. Its standard deviation is therefore about sqrt(dk). Scaling by sqrt(dk) brings that spread back near one. Learned correlations, different input scales or trained projections can violate those assumptions. Scaling does not guarantee bounded scores or equal weights.

Worked comparison / Do not confuse scaling with masking

Use a separate head with dk=4, query [2,0,0,0], keys [1,0,0,0] and [0,0,0,0], and scalar values 2 and 6. Raw scores are 2(1)+0+0+0=2 and 0. Without scaling, exponentials are approximately [7.389056,1], denominator 8.389056, weights [0.880797,0.119203]. The first value contribution is 0.880797(2), approximately 1.761594. The second is 0.119203(6), approximately 0.715218. Add them: 1.761594 + 0.715218, approximately 2.476812.

sqrt4=2, so scaled scores are [1,0]. Exponentials are [2.718282,1], sum 3.718282, weights approximately [0.731059,0.268941]. Contributions are 0.731059(2), approximately 1.462118, and 0.268941(6), approximately 1.613648. Their sum is approximately 3.075766. Both keys remain allowed. The divisor changed the distribution; it did not delete information access or reduce the output width.

Subtracting a maximum preserves the answer

Large exponentials can overflow a finite computer number. Numerical stability means evaluating an equivalent expression without unnecessarily producing problematic intermediate values. Subtract a row's maximum m from every permitted score. Since exp(s-m)=exp(s)/exp(m), all numerator and denominator terms share the same divisor and the weights stay unchanged.

Worked example / Stable arithmetic with a large common offset

For scores [1000,1000+ln3], do not calculate exp(1000). Subtract m=1000+ln3, giving [-ln3,0]. Exponentials are [1/3,1], sum 4/3. Weights are [(1/3)/(4/3),1/(4/3)]=[1/4,3/4]. With values 2 and 4, output is 0.5+3=3.5. This is exactly the mathematical distribution of [0,ln3] as well.

In finite floating-point arithmetic, a very negative shifted score can underflow to zero. That may be acceptable within an explicit precision tolerance, but it is not an exact real-number zero or a substitute for the logical mask. Reject unsupported nonfinite inputs instead of returning a success-shaped result.

Predict / Offset, scale and width

Compare softmax of [0,ln3] and [5,5+ln3]. Is dividing [0,ln3] by 2 also unchanged? For dk=64, calculate the scale divisor.

Reveal solution

The common offset 5 cancels, so both rows have [1/4,3/4]. Dividing changes the difference: exp((ln3)/2)=sqrt3, approximately 1.732051, giving weights approximately [0.366025,0.633975], not [1/4,3/4]. sqrt64=8 because 8(8)=64; divide scores by 8, not by 64 or by the model width.

4. Follow a small loss backward through the mixture

Attention is learned because its outputs can transmit loss sensitivities to value and matching projections. A derivative measures output change per very small input change at a particular input, not an exact prediction for any large step. For f(x)=x squared, changing x=2 to 2.001 changes f from 4 to 4.004001; the change ratio is 0.004001/0.001=4.001, approaching derivative 4 as the step shrinks. Chapter 2 teaches this limit.

Refresh chapter 2's chain rule: if changing x changes y, and changing y changes a loss, multiply the two local sensitivities to find that path's loss sensitivity. When several paths meet, add their contributions. A partial derivative measures sensitivity to one coordinate while holding the others fixed; a gradient collects those coordinate sensitivities. All the functions differentiated here are smooth for finite scores and a nonempty permitted key set.

We will use one query, two permitted keys, scalar values and dk=1, so the scale divisor is one. Let q=1, k1=0, k2=ln3, v1=2 and v2=4. Scores are [0,ln3], weights [1/4,3/4], output o=(1/4)(2)+(3/4)(4)=3.5. Choose target y=3 and squared-error loss L=(o-y) squared. This is a local teaching objective, not a language model's actual next-token loss.

Why one score affects the other weight

Write D=exp(s1)+exp(s2), a1=exp(s1)/D and a2=exp(s2)/D. D is a temporary positive denominator, not model width. The derivative of exp(s) with respect to s is exp(s). The quotient rule says the sensitivity of numerator n divided by denominator D is (n'D-nD')/D squared, where primes here mean derivatives and D squared means D times D. Its subtraction accounts for a denominator that also grows: let dn and dD name tiny changes in numerator and denominator. Then (n+dn)/(D+dD) differs from n/D by approximately dn/D minus n dD/D squared. Divide by the input step and take the limit to obtain the rule.

The partial symbol marks coordinate sensitivity, not a finite change. In the second equation, exp(s2) has derivative zero with respect to s1, while D grows by exp(s1). The same argument with positions exchanged gives own-score derivative a2(1-a2) and cross-score derivative -a1a2.

Worked backward pass / Both paths contribute

At scores [0,ln3], exponentials are [1,3] and D=4. The first quotient derivative has numerator 1(4) - 1(1) = 3 and denominator 4(4) = 16, giving 3/16. The cross derivative is -(3)(1)/16 = -3/16. Equivalently at weights [1/4,3/4], own-score sensitivities are (1/4)(3/4) = 3/16 = 0.1875 for a1 and (3/4)(1/4) = 3/16 for a2. Increasing s1 slightly raises a1 and lowers a2 by equal first-order amounts.

With o=a1v1+a2v2, output sensitivity to s1 adds v1(3/16) and v2(-3/16). Substitute the values: 2(3/16) - 4(3/16) = 6/16 - 12/16 = -6/16 = -0.375. For s2 it is 2(-3/16) + 4(3/16) = -6/16 + 12/16 = 0.375. Raising the score for the smaller value lowers the output.

Holding scores fixed, output sensitivity to v1 is a1=1/4 and to v2 is a2=3/4. L=(3.5-3) squared=0.25. Its derivative with respect to o is 2(o-y)=2(0.5)=1. Multiplying by this incoming sensitivity leaves score gradients [-0.375,0.375] and value gradients [0.25,0.75].

For any number of permitted scalar values, the same branch-sum reasoning simplifies to:

∂o∂sj=aj(vj−o)\frac{\partial o}{\partial s_j}=a_j(v_j-o)∂sj​∂o​=aj​(vj​−o)

j indexes one permitted key; o is the complete weighted output, not that key's value. The own path contributes vj aj(1-aj); all other paths contribute minus aj times their weighted values. Combine them: aj vj minus aj times the entire weighted sum, which is aj(vj-o). For vector values, apply this rule to each output coordinate and combine with its incoming loss sensitivity.

Worked backward pass / Queries, keys and a stored coefficient

Since sj=qkj at width one, its derivative with respect to q is kj; with respect to kj it is q. Thus dL/dq=(-0.375)(0)+(0.375)(ln3)=0.375ln3, approximately 0.411980. Each key receives dL/dkj=(dL/dsj)q, giving [-0.375,0.375]. Values still receive [0.25,0.75]; they are not used in the query-key dot products.

Suppose this query came from one projection q=xwQ with fixed x=2 and stored wQ=0.5. Then dq/dwQ=x=2, so dL/dwQ=2(0.375ln3)=0.75ln3, approximately 0.823959. A gradient-descent step subtracts learning rate times gradient. At learning rate 0.1, this coefficient becomes 0.5-0.1(0.823959), approximately 0.417604. This isolates one query-projection path while keeping K/V fixed; a real self-attention backward pass also adds the input's key/value paths and all query rows before updating shared parameters.

Saturation means the distribution is very concentrated. With a weight 0.999, its own-score derivative is 0.999(1-0.999)=0.000999; at 0.5 it is 0.5(0.5)=0.25. Small local weight derivatives can make some matching gradients small. Actual loss gradients also depend on values and incoming sensitivities, so concentration does not by itself prove all gradients vanish. Scaling helps manage score spread, not guarantee optimization.

Predict / A first-order change is not an exact new pass

Estimate the output change when s1 increases by 0.01 in our example. What if both permitted values equal 4? What happens to a mathematically excluded key's gradient?

Reveal solution

The first-order estimate is derivative times step: -0.375(0.01)=-0.00375, so estimated output is 3.49625. Recomputing softmax gives approximately 3.496241, not exactly the linear estimate. With values [4,4], o=4 and aj(vj-o)=0 for either score: changing the mixture cannot change equal values. A logically excluded key is absent from the row's normalization and mixture, so this row supplies no gradient through that key; it may still receive gradients from other queries that permit it. Logical mask selection is not a learned differentiable decision here.

5. Define access before normalizing

A causal mask permits a query at absolute position i to use key positions j at most i, including itself. That row predicts the following token, not the one it has already received. Refresh chapter 6's shifted targets: inputs [worker,lease,expired] can have targets [lease,expired,<end>]. A known training sequence allows parallel computation, but future input rows must not leak each row's target.

s~ij=sij+Mij,Mij={0j≤i−∞j>i\tilde{s}_{ij}=s_{ij}+M_{ij},\qquad M_{ij}=\begin{cases}0&j\leq i\\-\infty&j>i\end{cases}s~ij​=sij​+Mij​,Mij​={0−∞​j≤ij>i​

The tilde marks the masked score. M is an additive access mask, not a position vector. Negative infinity denotes exclusion: exp(z) tends to zero as z decreases without bound. A logical implementation can skip blocked keys rather than calculate infinities. A padding mask excludes nonexistent positions inserted for batch shape; combine it with causality when both apply. Each evaluated row needs at least one permitted key.

Worked example / Masking changes the denominator

Row 1's only exponential is 2, denominator 2, weight 2/2=1. It returns [2,0]. Row 2 has sum 1+3=4; output [(1/4)(2)+(3/4)(0),(1/4)(0)+(3/4)(4)]=[0.5,3]. Row 3 stays unchanged because all its keys are already causal.

A one-row decode query can see a long prefix

Suppose a cache contains absolute positions 1, 2, 3 and a new token occupies position 4. The decode Q tensor contains one row, but its position is 4. It must compare with keys 1 through 4, including the newly appended key. A naive mask j at most local row 1 would incorrectly permit only key 1.

Worked example / Locate the query before masking

Let P=3 be the cached prefix length and t=1 the new query's local position, counted from one. Its absolute position is i=P+t=4. The causal rule j at most P+t permits j=1,2,3,4. For a two-token chunk after the same prefix, local t=2 corresponds to absolute i=5 and permits keys 1 through 5, while chunk row 1 must not read the fifth key. This is not a universal API flag: read the attention library's alignment convention.

If padding removes every key in a row, the normalizer has no valid entries. Subtracting a maximum from all negative infinities can produce not-a-number values; returning zeros without a declared contract can hide a bug. Our code throws an explicit error. Serving/training libraries may handle padded query rows separately; that behavior must be intentional.

Predict / Combine two restrictions

In the three-row example, key 2 is padding. Recompute row 3. For one new query after five cached positions, which absolute position owns the query, and is key 6 allowed?

Reveal solution

Row 3 retains exponentials [2,6], sum 8, so weights over all keys are [1/4,0,3/4]. Output is [(1/4)(2)+(3/4)(2),(1/4)(0)+(3/4)(4)]=[2,3]. Padding changes the denominator independently of causal access. After P=5 cached positions, local t=1 belongs to position 6. Its own key 6 is allowed; later keys are not. Position rotations encode positions but do not replace this mask.

6. Heads are projections; axes preserve their ownership

Refresh chapter 6: multiple heads make separate query/key/value projections, calculate separate mixtures, concatenate coordinates and apply a learned output map. A head can use all input coordinates through its projection. Splitting a projected output into head-sized coordinate groups is not dividing the original embedding into isolated semantic chunks.

A tensor is an indexed array with any number of axes; each axis says what varies. Let B be batch examples and Hq query heads. A fused projection multiplies X of shape [B,N,d] by WQ of shape d-by-(Hq dk), producing [B,N,Hq dk]. A reshape exposes the head axis without changing numbers; then exchanging axes groups positions within each head.

Worked example / Two different views of the same permitted pair

7. Cross-attention has two sequence contracts

Self-attention draws Q/K/V from one sequence's current states. Cross-attention draws queries from a target-state sequence and keys/values from another source-state sequence. The comparison rule is unchanged, but its score table can be rectangular. An encoder-decoder commonly lets target queries read the entire already-known nonpadding source, while target self-attention remains causal.

Q=DWQ,K=SWK,V=SWVQ=DW_Q,\quad K=SW_K,\quad V=SW_VQ=DWQ​,K=SWK​,V=SWV​

D is Nt-by-dt target states; S is Ns-by-ds source states. Nt/Ns count positions, dt/ds count feature coordinates. WQ is dt-by-dk, WK is ds-by-dk, and WV is ds-by-dv. Scores have shape Nt-by-Ns; outputs are Nt-by-dv. D here means target states, not section 4's temporary denominator.

Worked example / Two targets query three sources

Choose D rows [1,0] and [0,1], and S rows [1,0],[0,1],[1,1]. Set WQ=diag(sqrt2,sqrt2), WK=diag(ln2,ln3), WV=diag(2,4), with both input widths two. The notation diag(a,b) means a two-by-two matrix with a and b on the diagonal and zeros elsewhere, as in section 1. The projected target queries are [sqrt2,0] and [0,sqrt2]; source keys/values are section 1's three rows.

The first target's scaled scores are [ln2,0,ln2], exponentials [2,1,2] and weights [2/5,1/5,2/5]. Its output is [8/5,12/5]. The second target's scores are [0,ln3,ln3], exponentials [1,3,3] and weights [1/7,3/7,3/7], output [8/7,24/7]. Score shape is 2-by-3, output 2-by-2. Neither result creates a third target token.

If source position 3 is padding, first-target exponentials [2,1] normalize by 3, giving output [(2/3)(2)+(1/3)(0),(2/3)(0)+(1/3)(4)]=[4/3,4/3]. The second target retains [1,3], sum 4, output [1/2,3]. A target's local position 1 does not by itself prohibit source position 2: source availability is a separate contract.

Retrieval obtains external information before or around model execution; putting those paragraphs into a decoder-only prompt does not add a cross-attention module. They are positions in the same combined self-attention context. Multimodal models, which process more than one kind of input such as text and images, may use cross-attention, a combined token sequence or other integration paths; inspect the model instead of assuming one universal design.

Predict / Read the rectangle

Reveal solution

If all source tokens are already available and nonpadding, source 7 can be read by target 1; causal target self-attention remains separate. Streaming source availability could require an additional explicitly designed restriction.

8. A sliding window changes which relationships are direct

Sliding-window attention restricts each query to a nearby range. Here it is causal and the positive integer width w includes self. At position i it permits keys from max(1,i-w+1) through i. The max operation chooses the larger number, ensuring the start never precedes position 1. This changes the model's access pattern, unlike an algorithm that evaluates full attention more efficiently.

Count paths without promising unlimited memory

A receptive field is the set of input positions that can potentially influence a state through the permitted computation paths. With the same width-three causal window at every layer, layer 1's state at position 6 reads inputs 4-6. Layer 2's position 6 reads layer-1 states 4-6; state 4 can read inputs 2-4. Their union is inputs 2-6, five positions. This is not equivalent to directly comparing position 6 against five original keys in one layer.

RL is the maximum count of consecutive input positions reachable at a late-enough position after L local-attention layers. L is a nonnegative integer; cap the count at the available prefix length. With no layers, only the input at that position is available, count 1. Each layer can extend the earliest possible dependency backward by w-1 positions. This formula assumes every layer has this same causal window and no global attention, other cross-position operations or special connectivity.

9. Prefill and decode use different query counts

Prefill processes known prompt positions and computes layer-specific keys and values. The final relevant prompt output supplies logits for the first continuation token. Decode then processes selected continuation tokens, usually one per step per sequence, to predict following tokens. Chapter 6 calculated the language-model head: it maps hidden coordinates to vocabulary logits; attention itself does not select tokens.

A KV cache stores computed key/value activations for reuse, not projection weights, final responses or external documents. Under deterministic causal computation, appending a future token does not change an old prefix state's permitted inputs. The old state's keys and values can therefore remain valid. This assumes compatible weights, token prefix, masks and position conventions; editing earlier text or changing a checkpoint can invalidate the cache.

Worked example / Cached and full causal arithmetic agree

Return to section 1's projections, used here as one causal attention layer with fixed incoming rows. Prefill positions 1 and 2 stores K=[[ln2,0],[0,ln3]] and V=[[2,0],[0,4]]. Position 2's causal output is [1/2,3]. A real downstream language head would use the final prompt state to select a new token; stipulate that its next incoming branch row is [1,1], matching our position 3 fixture.

Compute only that new row: Q3=[sqrt2,sqrt2], K3=[ln2,ln3], V3=[2,4]. Append K3/V3 to the two cached rows. Q3 compares with all three keys; scaled scores are [ln2,ln3,ln6], weights [2/11,3/11,6/11], output [16/11,36/11]. This equals row 3 of the full causal pass. The old queries are unnecessary for this new output.

In a multi-layer model, the new token's layer-2 input comes from layer 1's new output; layer 2 caches its own projected states, not a copy of layer 1's cache. Valid causal reuse applies through the stack. Bidirectional self-attention does not have the same append-invariance property: adding a new permitted future key can change earlier states.

Why batch size changes the execution picture

A matrix-matrix product can project several known token rows together. A single decode row's projection is a row-vector-by-matrix product. These operation shapes explain why one-request decode can expose different bottlenecks from a large prefill. They do not dictate every GPU kernel: batching independent requests, processing chunks or using another decoding algorithm can create multiple rows.

Worked example / Count only the projection

Take W with rows [1,2] and [3,4]. Prefill rows [1,0],[0,1],[1,1] produce [1,2],[3,4],[4,6]. There are three rows, two output columns, and two products per output: 3(2)(2)=12 scalar multiplications and 3(2)(1)=6 additions. A new row [2,1] alone gives [2(1)+1(3),2(2)+1(4)]=[5,8], using 1(2)(2)=4 multiplications and two additions. This excludes attention, FFNs, cache movement and kernel overhead; it is not an end-to-end latency estimate.

Predict / When must you recompute?

May you reuse a causal cache after replacing the first prompt token? Does ordinary next-token generation know token 5 before selecting token 4? Are old queries required for the cached third-row mixture?

Reveal solution

Replacing the first token can affect all following hidden states, so their cached keys/values cannot simply be reused as if the prefix were unchanged. Ordinary generation uses selected token 4 to compute the state predicting token 5; known training targets are a different situation. The new row needs Q3 and K/V1-3, not Q1/Q2. Reusing valid K/V removes repeated old computation, not the dependency on unknown selected tokens.

10. Sharing keys changes cache payload, not query ownership

MHA, conventional multi-head attention, has Hkv=Hq key/value heads. MQA, multi-query attention, has Hkv=1 shared key/value head. GQA, grouped-query attention, has fewer KV heads than query heads, each reused by a specified query group. Hkv counts pairs of key and value heads, not their combined total. These are learned architecture contracts; replacing MHA with GQA is not just choosing a smaller runtime cache.

Worked example / Same keys, different distributions

Choose Hq=4, Hkv=2 with groups {1,2} and {3,4}. In scalar-width group A, shared keys are [0,ln3] and values [2,4]. Head 1 query q=1 returns 3.5, as calculated earlier. Head 2 query q=-1 gives weights [3/4,1/4] and output 2.5. Sharing keys/values did not merge the queries or equalize their outputs. Group B can have different learned keys/values.

For equal-sized groups, group size is Hq/Hkv=4/2=2, requiring a compatible integer partition. With B=1, S=6 cached positions, dk=2 and dv=3, queries for one decode step have shape [1,4,1,2]. Cached keys are [1,2,6,2] and values [1,2,6,3]. Each query head uses its group's keys, yielding weights [1,4,1,6] and outputs [1,4,1,3]. Do not physically duplicate shared caches just to imitate the query axis unless your implementation explicitly requires it.

A stored scalar uses b bytes under a fixed data type; one byte is eight bits. Raw key/value payload is the number of stored scalar entries times bytes per entry. It excludes weights, temporary scores, allocator capacity, alignment, metadata and quantization scales. A total resident-memory estimate must account for those separately.

11. Count comparisons separately from allocated memory

Computational complexity describes how work grows as sizes grow, not a measured time. Big-O notation is an upper growth-rate description that omits constant factors and lower-order terms; saying quadratic here means the pair count is proportional to N squared for full attention. Actual time depends on implementation, parallelism, bandwidth and hardware.

For Nq query positions and Nk key positions per example/head, the dense score table has B Hq Nq Nk entries. Each query-key dot product uses dk multiplications and dk-1 additions. Mixing dv value coordinates uses dv multiplications per pair, and sums across keys for each output coordinate. These counts isolate the two matrix products; projections, scaling, masks, exponentials and backward work are additional.

Worked example / Full prefill at a small fixed width

Choose B=1, Hq=2, Nq=Nk=N=4, dk=dv=2. Pairs are 1(2)(4)(4)=32. Score multiplications: 32(2)=64; score additions: 32(2-1)=32. Weighted-value multiplications: 32(2)=64. There are 1(2)(4)(2)=16 output coordinates, each summing four terms using three additions: 16(3)=48. Thus the two products together use 128 multiplications and 80 additions.

If N doubles to 8, pairs become 1(2)(8)(8)=128, four times 32. Score and value multiplications total 128(2)+128(2)=512, four times 128. Addition counts are 128(1)+[1(2)(8)(2)](7)=128+224=352; these are not exactly four times 80 because sums use Nk-1 additions. Growth-rate shorthand is not exact operation accounting.

12. Tiling can preserve full attention without storing full weights

FlashAttention is an IO-aware attention algorithm: IO means data movement between memory levels. GPU high-bandwidth memory holds larger arrays; faster on-chip storage has limited capacity. A tile is a small block of queries/keys/values processed together. Rather than materialize every score and weight in large memory, the algorithm combines partial normalization and value sums. It computes the same permitted attention in real-number arithmetic, with possible floating-point differences from operation order.

Chapter 6 used two scalar values to introduce stable accumulation. Now we will merge a two-key tile with a third key and preserve both value coordinates. This is the algebra behind online softmax, not a GPU kernel, its full scheduling or its backward implementation.

Keep enough information to merge a tile

For processed permitted keys, keep the largest score m, an exponential sum l relative to m, and a vector z of weighted-value sums relative to m. l is a letter, not the numeral one; z has dv coordinates. At least one permitted key must be processed before initializing these values.

Worked example / First tile, keys 1 and 2

Use query 3 from section 2: scores [ln2,ln3,ln6], values [2,0],[0,4],[2,4]. The first tile's maximum is m=ln3. Its shifted exponentials are [exp(ln2-ln3),exp(0)]=[2/3,1]. Thus l=2/3+1=5/3.

Coordinate 1 of z is (2/3)(2)+1(0)=4/3. Coordinate 2 is (2/3)(0)+1(4)=4. Before the third key, the partial normalized output would be [(4/3)/(5/3),4/(5/3)]=[4/5,12/5]. This is attention over two keys only, not the finished output.

Merge under a common maximum

The second tile has score t=ln6 and value v=[2,4]. Set the updated maximum m'=max(m,t)=ln6. Old exponentials were measured relative to ln3, so rescale them by alpha=exp(m-m')=exp(ln3-ln6)=1/2. The new contribution has weight u=exp(t-m')=1. Primes here mean updated values, not derivatives.

l′=αl+u,z′=αz+uvl'=\alpha l+u,\qquad \mathbf{z}'=\alpha\mathbf{z}+u\mathbf{v}l′=αl+u,z′=αz+uv

Worked example / Finish both coordinates

l'=(1/2)(5/3)+1=5/6+6/6=11/6. First numerator coordinate: (1/2)(4/3)+1(2)=2/3+2=8/3. Second: (1/2)(4)+1(4)=2+4=6. Divide: o1=(8/3)/(11/6)=(8/3)(6/11)=16/11; o2=6/(11/6)=6(6/11)=36/11. This is exactly the full-row answer, without storing its three final weights.

For a general new tile, first compute its own maximum mt, denominator lt and vector numerator zt. Set m'=max(m,mt); multiply old sums by exp(m-m') and tile sums by exp(mt-m'), then add. This follows directly because both sums must use the same reference maximum. Initialize from the first nonempty permitted tile; skip fully blocked tiles. Changing tile order need not change the real-number result, but floating-point addition is not perfectly associative.

Full attention still evaluates its permitted query-key comparisons: tiling does not remove quadratic full-prefill arithmetic. Savings target intermediate storage, memory traffic and kernel efficiency. Cache storage is another cost; sharing KV heads addresses it differently. No universal speedup follows from this miniature calculation.

13. Implement the numerical contract in C#

This original CPU reference calculates one query row. It accepts Q/K/V already projected, uses finite double-precision numbers, a Boolean access mask, and an explicit positive scale divisor. Use sqrt(query width) for standard scaled attention; use 1 only for the deliberately unscaled comparison. It validates dimensions and reports unsupported inputs instead of silently manufacturing an answer. It is not a trained Transformer or a fast tensor kernel.

Predict the three causal outputs before running it. Copy the complete block into Program.cs of a local .NET 9 console project; no ML package is required. Inputs must be nonnull arrays with nonnull rows. Math.Exp computes the exponential, Math.Sqrt computes a square root, and bool[] explicitly describes allowed keys. Add one to a zero-based array index to obtain the chapter's one-based position: code index 0 is position 1.

using System;

static class AttentionReference
{
    static void RequireFinite(double[] row)
    {
        foreach (double value in row)
            if (!double.IsFinite(value))
                throw new ArgumentException("Entries must be finite.");
    }

    public static double[] Compute(
        double[] query, double[][] keys, double[][] values,
        bool[] allowed, double divisor)
    {
        if (query.Length == 0 || keys.Length == 0 ||
            keys.Length != values.Length ||
            keys.Length != allowed.Length ||
            !double.IsFinite(divisor) || divisor <= 0)
            throw new ArgumentException("Invalid row contract.");
        RequireFinite(query);
        int width = values[0].Length;
        if (width == 0)
            throw new ArgumentException("Value width must be positive.");
        var scores = new double[keys.Length];
        double maximum = double.NegativeInfinity;
        for (int j = 0; j < keys.Length; j++)
        {
            if (keys[j].Length != query.Length ||
                values[j].Length != width)
                throw new ArgumentException("Inconsistent widths.");
            RequireFinite(keys[j]);
            RequireFinite(values[j]);
            if (!allowed[j]) continue;
            double dot = 0;
            for (int r = 0; r < query.Length; r++)
                dot += query[r] * keys[j][r];
            scores[j] = dot / divisor;
            if (!double.IsFinite(scores[j]))
                throw new ArithmeticException("Score overflow.");
            maximum = Math.Max(maximum, scores[j]);
        }
        if (!double.IsFinite(maximum))
            throw new ArgumentException("No permitted key.");
        var weights = new double[keys.Length];
        double total = 0;
        for (int j = 0; j < keys.Length; j++)
        {
            if (!allowed[j]) continue;
            weights[j] = Math.Exp(scores[j] - maximum);
            total += weights[j];
        }
        var output = new double[width];
        for (int j = 0; j < keys.Length; j++)
        {
            if (!allowed[j]) continue;
            double weight = weights[j] / total;
            for (int c = 0; c < width; c++)
                output[c] += weight * values[j][c];
        }
        RequireFinite(output);
        return output;
    }

    public static void Main()
    {
        double root = Math.Sqrt(2);
        double[][] q = { new[] { root, 0.0 },
            new[] { 0.0, root }, new[] { root, root } };
        double[][] k = { new[] { Math.Log(2), 0.0 },
            new[] { 0.0, Math.Log(3) },
            new[] { Math.Log(2), Math.Log(3) } };
        double[][] v = { new[] { 2.0, 0.0 },
            new[] { 0.0, 4.0 }, new[] { 2.0, 4.0 } };
        for (int i = 0; i < q.Length; i++)
        {
            var mask = new bool[k.Length];
            for (int j = 0; j < mask.Length; j++)
                mask[j] = j <= i;
            double[] o = Compute(q[i], k, v, mask, root);
            Console.WriteLine(
                $"{i + 1}: [{o[0]:F6}, {o[1]:F6}]");
        }
    }
}

Each row calls the same function with a different query and mask. Blocked score-array entries are never used in the maximum, denominator or mixture. At least the maximum score has shifted exponential 1, so a valid finite row's denominator is positive. The code does not cache Q/K/V, update weights or select a vocabulary token.

Implement / Four useful extensions with checkable answers

Run all three queries without causality; add padding for key 2; calculate two scalar heads and combine them; compare a scaled and unscaled width-four row. Explain how a cached query at absolute position 4 gets its mask.

Reveal solution and implementation plan

For full attention, set every mask entry true. Outputs should be [1.6,2.4], [8/7,24/7] and [16/11,36/11]. For padding plus causality, use mask[j] = j <= i && j != 1; query 3 should return [2,3]. If the only causal key of a row is removed, the code intentionally throws rather than dividing by zero.

For the two-head check, call Compute with q=[1] and q=[-1], keys [[0],[ln3]], values [[2],[4]], mask [true,true], divisor 1. The outputs are [3.5] and [2.5]. Concatenate to [3.5,2.5] and multiply WO from section 6 to get [6,1]; no additional softmax is applied to joined coordinates.

For section 3's width-four query and keys, pass divisor 2 for scaled output approximately 3.075766 and divisor 1 for unscaled output approximately 2.476812. These are intentionally different operations. For a new query after three cached tokens, construct four allowed keys using its absolute position 4, not its local row 1. Test mismatched widths, empty allowed sets and nonfinite entries as errors. A production API may have another contract, but should not leave it implicit.

14. Interview questions

Explain each mechanism before quoting its abbreviation. These ten questions revisit the central contracts through different engineering decisions, not ten disconnected definitions.

01 / When does attention connect two sequences rather than contextualize one?

Explain the answer

Self-attention projects Q/K/V from one sequence's states. Cross-attention projects queries from a target sequence and K/V from a separate source. If there are two target and three source positions, the score table is 2-by-3, output still has two rows. Our first target normalizes [2,1,2] by 5 and mixes [2,0],[0,4],[2,4] to [8/5,12/5]. Available source positions do not obey the target's causal position numbering; source padding and target self-causality are separate restrictions. Adding retrieved text to one decoder prefix is not an architectural cross-attention module. Review the rectangular example.

02 / What parallelism does attention enable, and what remains dependent?

Explain the answer

Known positions can be projected and compared together within a layer, and permitted distant positions have direct attention paths. A recurrence instead uses its preceding state: for h_t=x_t+0.5h_(t-1), h0=0 and inputs [2,0,1], h1=2, h2=1, h3=1.5, in that order. Attention's three rows use a single 3-by-3 score operation instead of that recurrent state chain. However layer 2 still needs layer 1, and ordinary token 5 generation needs the selected token 4. Caching avoids repeated valid old K/V, not unknown-token dependencies. A quadratic full-prefill pair count is a tradeoff, not proof that one architecture always wins. Refresh the recurrence and review the generation timeline.

03 / Why distinguish a key from a value if both come from the same state?

Explain the answer

Q/K define matching scores; V defines contributed coordinates. Separate learned maps allow the matching and payload representations to differ. With q=1 and keys [0,ln3], scores normalize to [1/4,3/4]. Values [2,4] give output 3.5; changing the second value to 8 gives (1/4)(2)+(3/4)(8)=0.5+6=6.5 without changing those weights. A search-metadata/content analogy describes roles, not an actual document index or assigned semantic coordinates. Q/K/V are computed activations; WQ/WK/WV are stored parameters. Review projection arithmetic.

04 / Why scale by square root of key width, and why not call it a guarantee?

Explain the answer

Under approximately independent, centered unit-variance coordinate assumptions, adding dk query-key products yields variance about dk. A divisor sqrt(dk) therefore restores variance near one. At dk=4, divide raw scores [2,0] by 2 to get [1,0]. The larger weight changes from about 0.880797 to 0.731059. A saturated weight 0.999 has own-score sensitivity 0.000999, versus 0.25 at weight 0.5; scaling can help avoid excessively concentrated distributions. Trained correlations can violate the assumptions, and value/loss sensitivities also matter. The divisor concerns query/key width, not necessarily model width, and is not a causal mask. Review the variance table and the backward paths.

05 / How do MHA, GQA and MQA differ without deleting query heads?

Explain the answer

MHA has a KV head per query head; GQA shares each KV head among a specified query group; MQA shares one KV head among all queries. Four-query MHA/GQA/MQA with four/two/one KV heads under our B=1,L=2,S=6,dk=2,dv=3,b=2 assumptions use 480/240/120 payload bytes. GQA queries [1] and [-1] against shared keys [0,ln3] still return 3.5 and 2.5, because their scores differ. Cache storage follows Hkv, outputs and score rows Hq. Compatible projections/group mappings and training are required; changing allocation alone cannot invent a GQA checkpoint or guarantee a quality/speed tradeoff. Review shapes and group ownership.

06 / What exactly must a next-token causal mask prohibit?

Explain the answer

Query position i may use keys j at most i, including its own input, while predicting token i+1. It cannot use later input rows that expose the answer. Our row 2 retains exponentials [1,3], denominator 4, output [0.5,3]. Dropping the third term from weights normalized by 7 gives the wrong denominator. For one decode query after P=3 cached positions, local t=1 corresponds to absolute i=4, so keys 1-4 are allowed. Padding can impose additional exclusions, and an all-blocked row needs explicit handling. Position encodings do not enforce this access rule. Review the mask and offset examples.

07 / What does the KV cache save, and when is reuse valid?

Explain the answer

It saves layer-specific computed keys/values for a compatible causal prefix. Old states do not depend on newly appended future tokens, so the new query can reuse them. Appending section 9's K3/V3 gives scores [ln2,ln3,ln6], weights [2/11,3/11,6/11] and output [16/11,36/11], equal to full causal row 3. Each layer has its own cache; old query rows and final response text are not the cached payload. Editing the prefix, changing weights or position conventions can invalidate reuse. C=BLSHkv(dk+dv)b counts raw bytes, not every allocation or model tensor. Review reuse and the units.

08 / How can FlashAttention avoid full intermediate matrices and still be exact?

Explain the answer

Tiled computation keeps stable running maxima, exponential denominators and vector numerators. For scores [ln2,ln3] the first tile has m=ln3,l=5/3,z=[4/3,4]. The ln6 tile raises the maximum, so rescale old sums by 1/2 and add its exponential 1/value [2,4]: l'=11/6,z'=[8/3,6]. Dividing gives [16/11,36/11], the full-row result. Both numerator and denominator must use the same scale. This avoids materializing full weights in large memory; it does not remove permitted pair calculations or sparsify attention. Exact real-number algebra allows low-order floating-point differences, not arbitrary approximation or a universal benchmark claim. Review both tile orders.

09 / When is attention quadratic, and when is a step linear in context?

Explain the answer

Full prefill has N queries comparing with N keys per head: N squared pairs; score/value work grows with their widths. At B=1,Hq=2,N=4,dk=dv=2, the two products use 128 multiplications. N=8 gives 512, four times as many. Causal permitted pairs N(N+1)/2 still grow quadratically; a dense mask need not save allocated squares. One cached decode step has one new query per head against S keys, so work grows linearly in S: with S=4 the same widths use 32 multiplications, and S=8 uses 64. Summing many decode steps again accumulates growing work. Big-O is a growth description, not milliseconds, and KV cache payload is distinct from score intermediates. Review exact counts and assumptions.

10 / Does a high attention weight establish why an answer was produced?

Explain the answer

No. It describes one head/query's mixture, not a complete causal explanation of the final output. For weights [0.9,0.1] and scalar values [0,100], contributions are 0.9(0)=0 and 0.1(100)=10: the smaller weight supplies the entire scalar output. Vector directions can also cancel, and output projection, residual paths, FFNs and later layers change how mixed states affect logits. Heads may have overlapping or hard-to-interpret patterns. Attention also cannot retrieve an unseen external paragraph or authorize an action; RAG and permission checks are separate system operations. Review the scope of an attention inspection.

15. Audit the boundary before optimizing it

A useful inspection, not a complete explanation

Attention weights answer a narrow question: how did one head distribute its permitted value mixture for this query? They do not establish factual relevance, trust, grammatical specialization or a causal explanation of the generated answer. The counterexample weights [0.9,0.1] and values [0,100] produce output 10 entirely through the smaller-weight term. If values were [10,-90], the same weights would give 9-9=0: vector/scalar contributions can cancel.

RAG, retrieval-augmented generation, is an application pipeline that obtains external information and supplies selected text to a model. Attention ordinarily mixes representations already in the model's current permitted context. Retrieved text can enter a decoder prefix and then receive attention; high weight does not authenticate that text or authorize a tool call. The retrieval lesson in chapter 4 and application boundary in chapter 6 remain relevant.

Five contracts to retain

  • Projection: queries/keys match; values contribute. Define every axis before multiplying.
  • Normalization: each query has its own permitted denominator. Scale, mask and stable offsets solve different problems.
  • Learning: both matching and value paths transmit gradients. Add shared-input paths before updating parameters.
  • Reuse: cache valid layer-specific K/V, with correct positions and access. A cached step is not a full-prefill square.
  • Efficiency: windows change access, GQA changes sharing, tiling changes execution. Payload ratios are not benchmark results.

Synthesis / Audit a claimed optimization

An engineer says: "Four-query-head GQA with two KV heads makes full attention linear, and a one-row decode query can only read key 1. FlashAttention then deletes distant keys." Correct each claim. For B=1,L=2,S=6,dk=dv=2,b=2, calculate GQA cache bytes.

Reveal solution

Two KV heads reduce stored K/V, not the four query heads' full-prefix comparisons. Full prefill still has N squared comparisons per query head. A decode row's absolute position accounts for its cached prefix: after five old positions, its local row 1 corresponds to position 6 and may read keys 1-6. FlashAttention evaluates the specified permitted set with tiled stable accumulation; a sliding window, not exact full-attention tiling, excludes distant keys.

Payload is 1(2)(6)(2)(2+2)(2). Compute 1(2)=2, then 2(6)=12, 12(2)=24, 24(4)=96 scalars, and 96(2)=192 bytes. Model weights, intermediates, allocation overhead and data-type metadata are excluded. A correct payload number alone cannot certify a faster or more accurate serving implementation.
