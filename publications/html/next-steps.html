From foundations to engineering practice

Use the tools you have built

You can now follow how text becomes IDs and vectors, how gradients change parameters, and how attention combines permitted context. You can inspect shapes before multiplying, distinguish an activation from a parameter, and ask what a cache or operation count actually includes.

Start a small notebook of reproducible checks. Recalculate a tokenizer path, perturb one weight, or compare cached and full causal attention on the same toy inputs. Keep the exact assumptions alongside each result.

Carry these questions into real systems

When you build with a model, ask what data enters it, which version and tokenizer your application uses, what evidence supports an output, and how failures will be detected. Measure latency and memory under your workload rather than deriving a production claim from a tiny example.

Retrieval, evaluation, security boundaries, deployment and operations deserve their own careful engineering work. The current chapters give you a foundation for that work; they do not replace a system design, a threat model or an evaluation plan.

Return to a difficult example

If you cannot yet explain a derivative path, a RoPE rotation or a tile merge in your own words, return to its smallest numerical case. Name each intermediate result and why the next step uses it. Progress is not measured by the speed at which you reach the last page.

The next useful milestone is a result you can reproduce, interpret and challenge. Keep that standard as the book grows.
